## 2. Behaviour

### 2.1 Email (mocked fare: TPE-TYO, 2026-12-11 to 2026-12-18, NT$8,062, marker set)

```
✈️ 台北 → 東京 參考票價 約 NT$8,062（已低於你的目標價）

參考票價（來源：Aviasales）：約 NT$8,062
你的目標價：NT$9,000
去程 2026-12-11  回程 2026-12-18（來回）
航空公司：長榮航空（BR）

[在 Skyscanner 搜尋此行程]                                   primary button
[在 Trip.com 搜尋此行程]                                     secondary button
在 Aviasales 搜尋此行程（票價來源・聯盟連結・英文介面）        text link, always present
在 Google 航班自行搜尋（需手動輸入航線與日期）                 text link

參考票價來自 Aviasales（經 Travelpayouts 取得），已換算為新台幣，金額為約略值，可能已變動。各平台顯示的價格與可訂位情況可能不同，實際價格以訂購網站為準。
本服務可能因你透過 Aviasales 連結訂購而獲得佣金。
```

- 「立即訂購」 is gone. When the price equals the target, the headline says 「已達你的目標價」.
- The plain-text part has the same lines, with each link as `label：url`.
- Links open in a new tab with `rel="noopener noreferrer"`. Everything is HTML-escaped.
- When any platform falls back, the email adds 「部分平台的連結無法直接帶入此行程，請自行確認航線與日期。」
  and each fallback label says 「需自行確認航線與日期」.
- The affiliate disclosure appears only when the Aviasales affiliate link does.

### 2.2 Generated links

| Platform | Itinerary link when | Otherwise | Locale / currency |
|---|---|---|---|
| Skyscanner | both codes in its `verified_codes` (TPE, RMQ, TYO, OKA) and dates valid | `https://www.skyscanner.com.tw/` | `locale=zh-TW&currency=TWD&market=TW` (documented parameters) |
| Trip.com | both codes in its `verified_codes` (TPE, KHH, RMQ, TYO, OKA) and dates valid | `https://tw.trip.com/flights/` | `locale=zh-TW&curr=TWD` (observed, not documented) |
| Aviasales | any catalog route, dates valid and return before the same day next year | `https://www.aviasales.com/` (with the marker) | none exists; label says 英文介面 |
| Google Flights | never (no documented deep link) | `https://www.google.com/travel/flights?hl=zh-TW` | `hl=zh-TW` only |

Fixed for every link: 1 adult, economy, round trip. A link is never one-way.

### 2.3 The Aviasales marker (Travelpayouts condition 3)

- Source: environment variable **`TP_MARKER`** on the v2 notification Lambda, set at deploy time.
  It is never in the repository; validation rejects any 5+ digit number, `marker=`, token,
  secret or `eyJ` string in `search-platforms.json`. Tests use the obvious fake `000000`.
- Accepted format: 3–12 ASCII digits (Travelpayouts' documented example is numeric). SubIDs
  (`.subid`) are documented by Travelpayouts but unused, so a dot is rejected.
- Appended as exactly one `marker` parameter, on Aviasales links only (L09).
- **Fail closed.** With no marker, or one in an unexpected format, the email shows **only the
  plain Aviasales link** (no affiliate label, no disclosure) and suppresses Skyscanner, Trip.com
  and Google Flights. This keeps condition 3: other platforms are never shown without the
  labelled Aviasales affiliate link. The Lambda logs one line saying so, without the value.

### 2.4 Failure handling (spec §6)

| Situation | Result |
|---|---|
| Code not in the catalog, lower-case, `TSA` as origin, empty, 4 letters, injection | No links; email still sent; log `links: unsupported_code` |
| Missing, malformed, past, outside the window, or return before departure | Every platform's fallback with the notice |
| Codes not verified for a platform | That platform's fallback; others unaffected |
| Platform `enabled: false` | Omitted; others unaffected |
| Builder raises | Email sent without the links section; log `links: error <ExceptionName>` |
| Bundled config invalid at start-up | Links disabled (email unaffected); the package build already refuses such a file |
| `EMAIL_TEMPLATE=m1` | M1 email, byte-identical to production (parity test) |

### 2.5 Deviations from, and corrections to, the spec

1. **Aviasales year ambiguity (spec §4.2 was wrong).** The spec said the 13-month window keeps
   the year-less DDMM path unambiguous. It doesn't: a return date 12–13 months away reads as a
   date in the past. Aviasales now gets its fallback (home page with marker) when the return date
   is on or after the same day next year; Skyscanner and Trip.com keep their itinerary links.
2. **L12 "no marker" is enforced at run time, not at build time.** The marker is deploy-time
   data, so the build can't see it. The build enforces the configuration half (Aviasales
   affiliate block enabled and required whenever another platform is enabled); the run time
   enforces the marker half (§2.3).
3. Google Flights label follows the §2.1 mock-up: 「在 Google 航班自行搜尋（需手動輸入航線與日期）」.
4. Missing dates are shown as 「未提供」 instead of an empty string.

Nothing here is deployed. Before the v2 notification Lambda can carry these links:

- every Phase 2B-1 deployment blocker still applies (dedup pepper parameter, new IAM
  permissions, B5 rounds 2–3, the deployment change set; see the 2B-1 doc);

- a test-inbox render on the three origins (spec §7.2) while Resend stays in testing mode;
- EventBridge stays disabled and automatic production emails stay off until the owner decides.

Rollback: setting `EMAIL_TEMPLATE=m1` (an environment change, no new code) restores the M1 email.
Switching a platform off is a one-line change in `search-platforms.json` and a rebuild of the
ZIP; no code changes.
